## General Themes and Patterns

1. Event-driven development: Many files were tuned for a specific Halloween 2025
   event and those event-specific values leaked into templates and defaults.

2. Planning docs committed to source: 9 markdown files totaling ~2400 lines of
   internal planning, status tracking, and research that belong in a wiki or
   project management tool, not version control.

3. Hardware-specific scripts: 4 deployment scripts with hardcoded paths, device
   indices, and IP addresses for a specific deployment target.

4. Stub/placeholder code: UserProfile class with do-nothing methods scattered
   through the codebase, creating the illusion of functionality.

5. Incorrect comments: Comments describing behavior that doesn't match the code
   (reverb/bass boost that doesn't exist, "slower" speed that's actually normal).

6. Dead imports: Multiple files importing symbols that are never used, left over
   from refactoring during the 54-commit PR.

7. Diagnostic tools committed as production code: Debug/calibration utilities
   that should live in a separate tools/ repo or be run ad-hoc.


## Suggested Gates to Prevent This in Future PRs

1. Pre-merge file checklist: Block PRs that add files matching patterns like
   *.desktop, *_SETUP.md, *_PLAN.md, STATUS.md, or files in deployment/.

2. .gitignore enforcement: CI check that no tracked files match .gitignore
   patterns (catches the .cursor symlink contradiction).

3. Dead code detection: Run vulture or similar tool in CI to catch unused
   imports and dead stub classes.

4. Comment lint: Flag TODO comments without issue references, commented-out
   code blocks, and comments containing "hack", "temporary", or "WIP".

5. Config template validation: Ensure template files use documented default
   values, not environment-specific tuning.

6. PR size limits: Flag PRs over 20 commits for mandatory architecture review
   before merge.

7. Separate deployment from application: Hardware-specific scripts, desktop
   entries, and watchdog processes should live in a separate deployment repo
   or at minimum a clearly marked deployment/ directory in .gitignore.

8. No planning docs in source: Add *.md exclusion for root-level markdown
   (except README.md, CONTRIBUTING.md, CHANGELOG.md) to prevent status/planning
   docs from being committed.

9. Test isolation: Ensure tests can be collected and run without external API
   keys. Module-level API client initialization should be deferred.

### Test Infrastructure Issues

1. requirements_test.txt was missing -r requirements_core.txt. Running
   `pip install -r requirements_test.txt` alone did NOT provide all deps needed
   for test collection. Modules imported at collection time (blessed, pyaudio,
   psutil, SpeechRecognition, keyboard, gTTS, google-cloud-speech, soundfile,
   etc.) were all missing. Fixed by adding the include.

2. ttv/story_generation.py:10 created an OpenAI client at module import time:
   `client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))`. This caused
   ALL tests that transitively imported this module to fail collection when
   OPENAI_API_KEY was unset. Replaced with lazy _get_openai_client() getter
   that defers initialization and warns at first use.

3. Dockerfile had a redundant `pip install -r requirements_core.txt` after
   installing requirements_test.txt. Since requirements_test.txt now includes
   requirements_core.txt via -r, the separate install was removed.

4. tests/unit/ttv/test_story_generation.py patched the now-removed module-level
   `client` variable. Updated to patch the new `_get_openai_client` function.
