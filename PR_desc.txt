### 6. General Themes and Patterns in What Went Wrong

1. **Deadline-driven commits**: "WIP" commits (e.g., "WIP ganglia 2025 halloween", "WIP realtime stuffs") were merged without cleanup, though the WIP files themselves were later removed

2. **Environment-specific artifacts**: Developer machine paths (.cursor symlink) leaked into the repo

3. **Missing f-string prefixes**: Easy to miss during review, caused silent bugs

4. **Bypassing established patterns**: Using raw `print()` instead of the Logger system

5. **Self-aware bad code**: Comments like `# Constant should be uppercase but used locally` show awareness of issues without fixing them

6. **Temporary/event-specific configs**: Halloween-tuned settings committed as defaults

7. **Stub code without clear markers**: Placeholder implementations mixed with production code

---

### 7. Suggested Gates to Prevent This in Future PRs

1. **Pre-commit hooks**:
   - Lint for missing f-string prefixes when `{` appears in regular strings
   - Block commits of symlinks
   - Block raw `print()` calls (require Logger usage)
   - Flag "WIP", "TODO", "FIXME" in commit messages

2. **CI checks**:
   - Run `git diff --check` to catch whitespace errors and symlinks
   - Static analysis for string formatting issues (pylint has rules for this)
   - Check for hardcoded paths containing `/Users/` or `C:\Users\`

3. **PR review checklist**:
   - [ ] No WIP commits without squashing
   - [ ] No environment-specific paths or symlinks
   - [ ] All print statements use Logger
   - [ ] Magic numbers are defined as constants
   - [ ] Stub/placeholder code is clearly documented
   - [ ] Config defaults are production-appropriate, not event-specific

4. **Branch policies**:
   - Require squash merging for feature branches with many commits
   - Require passing CI before merge
   - Require at least one approval with checklist completed
