### 6. General Themes and Patterns in What Went Wrong

1. **Deadline-driven commits**: "WIP" commits (e.g., "WIP ganglia 2025 halloween", "WIP realtime stuffs") were merged without cleanup, though the WIP files themselves were later removed

2. **Environment-specific artifacts**: Developer machine paths (.cursor symlink) leaked into the repo

3. **Missing f-string prefixes**: Easy to miss during review, caused silent bugs

4. **Bypassing established patterns**: Using raw `print()` instead of the Logger system

5. **Self-aware bad code**: Comments like `# Constant should be uppercase but used locally` show awareness of issues without fixing them

6. **Temporary/event-specific configs**: Halloween-tuned settings committed as defaults

7. **Stub code without clear markers**: Placeholder implementations mixed with production code

---

### 7. Suggested Gates to Prevent This in Future PRs

1. **Pre-commit hooks**:
   - Lint for missing f-string prefixes when `{` appears in regular strings
   - Block commits of symlinks
   - Block raw `print()` calls (require Logger usage)
   - Flag "WIP", "TODO", "FIXME" in commit messages

2. **CI checks**:
   - Run `git diff --check` to catch whitespace errors and symlinks
   - Static analysis for string formatting issues (pylint has rules for this)
   - Check for hardcoded paths containing `/Users/` or `C:\Users\`

3. **PR review checklist**:
   - [ ] No WIP commits without squashing
   - [ ] No environment-specific paths or symlinks
   - [ ] All print statements use Logger
   - [ ] Magic numbers are defined as constants
   - [ ] Stub/placeholder code is clearly documented
   - [ ] Config defaults are production-appropriate, not event-specific

4. **Branch policies**:
   - Require squash merging for feature branches with many commits
   - Require passing CI before merge
   - Require at least one approval with checklist completed

## Additional Test Infrastructure Fixes

### Problem
Tests were failing at **collection time** when API keys (OPENAI_API_KEY, FOXAI_SUNO_API_KEY, etc.) were not set, because:
1. `ttv/story_generation.py` created OpenAI client at module import time
2. `music_lib.py` raised errors when initializing fallback backends without API keys
3. Tests raised EnvironmentError instead of skipping when credentials missing

### Solution

**Lazy client initialization** (`ttv/story_generation.py`):
- Changed module-level `client = OpenAI(...)` to lazy `_get_openai_client()` function
- Client only created when actually needed, not at import time

**Graceful fallback handling** (`music_lib.py`):
- Wrapped FoxAISunoBackend initialization in try/except
- If API key missing, fallback is set to None with a warning instead of raising

**Test skip fixtures** (`tests/conftest.py`):
- Added `requires_openai_key`, `requires_google_credentials`, `requires_suno_key` fixtures
- Tests using these fixtures are skipped (not failed) when credentials unavailable
- Warnings logged at test session start about missing API keys

**Updated tests**:
- `test_send_query.py`, `test_query_dispatch.py` - use `requires_openai_key`
- `test_generate_poster.py`, `test_generate_lyrics.py` - use `requires_openai_key`
- `test_audio_alignment.py` - use `requires_google_credentials`
- `test_music_lib.py` - updated assertions to handle None fallback
- `test_story_generation.py` - updated mock to use `_get_openai_client`

### Result
- Tests now **skip gracefully** instead of failing when API keys are missing
- Test collection no longer fails on import errors
- 128 passed, 19 skipped, 3 failed (runtime Google TTS issues, not collection failures)
